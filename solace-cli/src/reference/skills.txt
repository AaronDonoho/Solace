Skills (D-27): the `skills` key in solace.toml names a project's skills
folder, `skills/` when the key is missing. Each skill is a subfolder with a
`SKILL.md`, or a single `<name>.md` file at the folder's top; `name`,
`description` and optional `roles` are front matter between `---` lines, and a
skill with no description is listed by its first line. `roles` holds
comma-separated role ids (strategist, investigator, worker, reviewer,
coordinator): a skill with `roles` reaches only a run in those roles, and its
whole text goes in that run's brief; a skill naming no roles reaches no run;
a skill with no `roles` key reaches every role, listed one line with its name,
description and the path to `read`. Every run's brief (work, investigate,
discuss, review, strategy) also carries the skills saved on Settings in the
workspace root's skills folder, so a skill saved once applies to every project
in the workspace. Settings lists every skill in that folder. It manages the
single-file skills whose front matter has a `roles` key: add, edit or remove
them there with a name, a one-line description and a body. A saved skill may
name no roles, and Settings shows it as "Not used by any role". Roles are
chosen in each agent role's card, which lists every skill in the folder and
saves a tick straight away. Skills written by hand keep working: a file with
no `roles` key is listed to every role as before and Settings labels it "All
roles" and leaves its file alone; a folder skill is likewise left to its
human. A name becomes a file name, so names use only letters, digits, spaces,
`-` and `_`; `README` and a name a folder skill uses are refused. A body is at
most 1000 characters, and an empty name or body is refused before anything is
written.
The humans own the folder: agents read skills and change none of them. Solace
never runs a skill's scripts: a skill that needs a tool names a `[commands]`
entry the human adds to solace.toml, run with `run <name>` (as `layout_audit`
is). A `README.md` at the folder's top is the folder's own note, not a skill.
The key names a folder inside the project that holds no code: `src`, `test`, a
folder inside them, `.solace`, a nested project (one with its own store) and a
folder inside one are refused; `./x` names the same folder as `x`.
