Rust projects

Names
  `<module>.<item>`             a free function: `testing.rust_project`
  `<module>.<Type>::<method>`   a method: `crate.Store::resolve_module`, named
                                by the module holding the `impl`, not the type's;
                                generics may be left out (`Refs::new`) when one
                                impl matches
  `<module>.<Type as Trait>`    a trait impl, such as
                                `crate.<Failure as From<std::io::Error>>`; its
                                method adds `::<method>`, as in
                                `crate.<Failure as From<std::io::Error>>::from`.
                                Spaces inside `<…>` are part of the name; a
                                command keeps them together, so type it as shown
  `<module>.tests::<name>`      an item in a test module, inline or a file:
                                `drafts.tests::rejected_text_survives_and_retries_atomically`
  `crate`                       the crate root; `crate.Store::resolve_module`
                                is a method there
  view <module>                 lists the real names; E1001's "Similar names"
                                line gives the one to use

Adding
  submit --new <module>         a function, or a whole `impl`, `trait`, inline
                                `mod` or `extern` block with its items
  submit --new <module>.<Type>  a method: `submit --new crate.Store`
  submit --new <module>.tests   a test module in `<module>_tests.rs`, declared
                                with `#[cfg(test)]` and `#[path]`; also
                                `<module>::tests`; its items come from the
                                submitted text
  submit --imports <module>     a module's header: module comment and imports;
                                for an inline `mod`, only the lines after its
                                `{`. Its own `mod` lines are kept (`view
                                <module> --header` shows it). The header keeps
                                the submitted text's trailing newlines, or one
                                when it has none.
  submit <module>               a whole module: keep every stored item; ids
                                stay by name, and only changed items are reformatted
  submit <container>            an existing block changes item by item; submit
                                its items instead
  submit --new <parent>::<new>  a new module: `submit --new store::notes`;
                                `integration::x` makes `tests/x.rs`
  *** Add: a::b::c              in a patch, creates the module
                                An Add whose only item has the module's own
                                name is refused: use the dotted form, e.g.
                                `*** Add: m.f` instead of `*** Add: m::f`.

Moving
  extract <name>... --to <module>
                                moves items with their ids, then checks with
                                cargo or changes nothing. A method is
                                `Type::method` (`Store::find` works when one
                                impl matches); a short name two symbols share
                                is refused and listed (E1002): write the
                                module, `store_core.has_column`, or
                                `crate.has_column` for the crate root's. Moved
                                methods join an `impl` of their type in the
                                target; methods of one impl per call, and a
                                trait impl only whole (E6013). A whole
                                inherent impl is named `<Type>`. Imports the
                                moved code used come with it; one a staying
                                module reaches through a glob stays in place.
  --to <new module>             a module the store lacks is created: `helpers`
                                beside the crate root (`src/helpers.rs`),
                                `store::read` in `src/store/read.rs`. Its
                                parent gets `mod <name>;` after its last `mod`
                                line (`pub mod` when a plain `pub` crate-root
                                item moves in). The file starts with the moved
                                code and its imports: add a module comment with
                                `submit --imports <module>`.
  helpers                       a private free function, const or static that
                                only moved code uses comes along
                                (`+1 helper:`). One that staying code or a
                                staying test also uses stays; the moved call
                                is rewritten, by a path such as
                                `crate::matches(…)` or by an import. A private
                                method never comes along: it stays in its
                                impl and is raised to `pub(crate)` when the
                                target can't see it.
  tests                         a test moves only when everything it calls,
                                directly or through a fixture in its test
                                module, moves too. A test whose `sample()`
                                fixture calls staying `Store::new` stays.
                                The reply is `Tests staying: N`, plus
                                `(rewritten: …)` for tests whose text or
                                imports changed. A moved test goes to the
                                target's `tests` file module when its header
                                declares one, else to a new `<target>::tests`
                                beside the target's file (`src/helpers_tests.rs`,
                                `src/board/reviews_tests.rs`). An inline test
                                module whose tests all move moves inline,
                                keeping its name; a file test module that
                                empties is retired, and its tests join
                                `<target>::tests`.
  visibility                    named in the reply. A moved item that
                                staying code outside the target calls becomes
                                `pub(crate)` (`Now pub(crate): search.Store::count`);
                                a staying private item, or the fields of a
                                staying type, the moved code uses become
                                `pub(crate)` unless the target is inside their
                                module. A `mod` line on the way to the target
                                is raised only as far as callers need: to
                                `pub(super)` or `pub(crate)`, or `pub` when a
                                plain `pub` crate-root item moved
                                (`Now pub(crate): mod x`; D-211).
  refusals                      E1001 `<file> already exists`: the target's
                                test file name is taken, even by another
                                module's tests (`store_read_tests.rs` holds
                                `store::read_tests`); choose another target,
                                such as `store::read` (`src/store/read_tests.rs`).
                                E1004 `<target>.tests already exists`: the
                                target already has a `tests` module it can't
                                take. E1004 `<target>.<name> already exists`:
                                a name clash.
Example: `Store` has private `find` and `count`, a private free `matches`,
`report` calls `count`, and `count_counts` calls `sample()`, whose fixture
calls the staying `Store::new`. Moving `find` and `count` to a new `search`:
  extract crate.Store::find crate.Store::count --to search
  Moved crate.Store::find, crate.Store::count (+1 helper: matches) to search
  Tests staying: 1
  Created module search (src/search.rs)
  Now pub(crate): search.Store::count
  Rewrote references in 1 symbol
`find` stays private because only moved `count` calls it; `count` becomes
`pub(crate)` because `report` stays; `matches` moves; `count_counts` stays
because its fixture reaches the staying `Store::new`.

Formatting
  format <module>               rustfmt the whole module, with the project's
                                rustfmt.toml and edition; its ids stay by name.
                                A file that differs from the store (E0104) is
                                replaced by the store's text; its copy is kept
                                under .solace/outside/
  submit                        formats only the items its text changes

Searching
  find <text>                   finds Rust source, e.g. `find resolve_module`
  grep <text>                   does not search Rust source; it searches other
                                files and settings, and with `--in <file>` a
                                text file over the watch limit, e.g. `grep rust-unit`

Details: `check`, `test` and `build` run cargo and locate errors and failures
by symbol and libtest name. `delete` removes an item with the items it holds;
a module this empties loses its file and `mod` line; `delete` refuses a name
cargo still uses (E5001).
A new module's name must be an identifier `syn` reads; a keyword or `_` is
refused. `refs` lists a method name as a possible use; `impact` and
`inspect --context` count it. A name a local binding, a module's own item, or
a named import hides is not a use.
On Linux, cargo runs in a sandbox with no network and only `target/` writable,
so dependencies are fetched after an import or an approved Cargo.toml change;
without `cargo`, those commands are refused.
`submit` and `format` name an item and the lines rustfmt leaves longer than
`max_width`: rustfmt left them as written, so check their indentation or split
the long literal.
