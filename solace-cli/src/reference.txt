Solace: this project's code lives in a semantic store. You read and change it
one symbol (a function, type or constant) at a time. You cannot open files.

Names: a symbol is `module.name`, e.g. `pilot/checkout.pay`. Any unambiguous
suffix works: `checkout.pay`, or just `pay` if only one symbol has that name.
Modules: `pilot/checkout`, or just `checkout`. Tests are symbols too, in test
modules such as `pilot/checkout_test`.

Several commands can go in one tool call, one per line; they run in order.

Solace is your only way to work on the project. When it can't do something the
task needs (a file you may not write, a command that isn't declared), don't
work around it: ask with `task ask`, or say so in your summary.

Reading (the symbol list above usually tells you what to inspect; ask for
several symbols in one call rather than one at a time). Read symbols, not
modules: `inspect a b c --context`. Use `--bodies` only for a module you will
rewrite most of. `--context` includes a test that uses each symbol, as an
example. Replies stay under a size limit: a signature is printed once per
reply, and a reply that would be larger says what it left out and the command
that shows it.
  solace session start --task     (the task in `text`) the symbols most likely
                                  relevant to it, the modules, open work
  solace session start [--scope <module>...]
                                  every symbol, open work records with the
                                  context they need
  solace inspect <name>... --context
                                  each symbol, plus the signatures of everything
                                  it uses, everything that uses it, and the
                                  tests that use it (the smallest in full)
  solace view <name>...           symbols' source
  solace view <module>...         module outlines: signatures and doc lines
  solace view <module> --bodies   whole modules' source
  solace refs <name>              everything that uses a symbol
  solace find <text>              case-insensitive search of all code, showing
                                  matching lines per symbol

Changing (the new code is the tool's `text` argument; from a shell, stdin)
  solace submit <name>            replace a symbol with new code (may rename it)
  solace submit <name> --replace  change one part of a symbol: `old` is the
                                  exact current text (must occur once), `text`
                                  its replacement; the whole symbol is checked
  solace submit --new <module>    add a symbol to a module; a module that doesn't
                                  exist yet is created (under test/ if its name
                                  ends in `_test`, otherwise src/)
  solace submit                   several symbols at once, checked together
                                  (e.g. a type and its callers): blocks each
                                  headed `// ── <module>.<name> ──`, as view
                                  and inspect print them; a new name adds it
  solace submit <module>          replace a whole module, as `view --bodies`
                                  shows it; it must still contain every
                                  existing symbol
  solace submit --imports <module>
                                  replace a module's imports and module comment
  solace delete <name>            remove a symbol (refused while anything uses it)

  Each submit is type-checked. If the submitted symbol has errors, nothing is
  saved. If it breaks other symbols (e.g. callers of a changed signature), it is
  saved and those are listed as broken until fixed. Missing imports are added
  automatically (for `module.name` references and for unqualified types and
  constructors such as `Option` or `None`); imports in submitted text are
  merged into the module's imports.

Checking
  solace check                    type-check everything; lists broken symbols
  solace test                     run all tests; shows failures only

Work records (persist between sessions)
  solace work add <text> (or the tool's `text`) | solace work list | solace work done <id>

Files (solace.toml is human-owned)
  files [dir]                         tree with tiers; internal files have no access
  read path [--lines a..b | --tail n]  read manifest/resources/ignored files/settings
  write path                         whole text (read an existing file first)
  write path --replace               exact `old` -> `text`; CLI: --old <text>
  remove path                        remove a declared resource

Project commands
  build                               compile the project
  format                              format the project's code
  run name [args...]                  only commands declared in solace.toml

Read-only runs (reviews, investigations) can read, check, test and build;
submit, delete, write, remove, format and run are refused.

Task runs (put the note, summary or question in `text`)
  task note                           add a note; completes a review run
  task ask                            question in `text`, 2–4 `options`; waits
                                      for the human's answer
                                      CLI: --option <label> repeated, question on stdin
  task done                           finish: a work run's summary goes to human
                                      review; an investigation's report stays on
                                      the task

Host commands (humans only, refused in a run)
  serve [--port N]                    local task board (default 3030)
  agent-config codex|claude dir       isolated settings and launch.json for a runner
